COMP410 Sprint 3 - Team Z - AI prompt used to build the PII redactor
=====================================================================

PROMPT (version 1)
------------------
You are helping a college software engineering team build a small Python
application that detects and redacts personally identifiable information (PII).

Context
- The repo has pii_scan.py with two functions we must use:
  anonymize_text(text: str, entity_list: list) -> str   (returns redacted text)
  analyze_text(text: str, entity_list: list) -> list    (returns Presidio results)
- Presidio replaces each PII span with a tag such as <PHONE_NUMBER>.
- Our team (Team Z) is only responsible for these entities:
  PHONE_NUMBER, LOCATION, PERSON, UK_NHS, UK_NINO

Requirements
1. Create pii_redactor.py with a function redact_text(text, entities=None) that
   calls anonymize_text() from pii_scan.py and returns the original text with
   PII redacted. All non PII text must stay exactly the same.
2. The app must accept an entity list and the text to anonymize. The entity list
   can be a Python list or a comma separated string, in any letter case.
3. Reject entity names outside our five supported entities with a clear error.
4. Handle bad input without crashing: non string text, empty text, whitespace
   only text, and a missing file. Show the user a friendly message.
5. Important: an empty entity list makes Presidio scan for EVERY entity type,
   so treat an empty or missing list as "all five Team Z entities".
6. Add a command line interface with --entities, --text, --input, --output and
   --summary options.
7. Extras: a summarize() function that counts detections per entity type, a
   batch mode that redacts line by line, and file in / file out processing.
8. Write readable code with docstrings and no duplicated logic.
9. Write unittest tests in test_sprint3_team_z.py covering: each of our five
   entities, multiple occurrences, mixed entities, no PII, empty input,
   whitespace input, invalid entity names, invalid input types, and files.

Output format: full file contents, one code block per file.

FOLLOW UP PROMPT (version 2, web app)
-------------------------------------
Now update the existing Flask app in pii_web_app.py so it uses redact_lines()
and summarize() from pii_redactor.py instead of calling anonymize_text()
directly. Requirements:
- Show the five supported Team Z entities on the page.
- Blank entity box means all five entities.
- Catch RedactorError and show it as a friendly red message on the page.
- Show a message if the text box is empty.
- Show how many of each entity type were found under the result.
- Add a Load example button that fills the text box with a sample paragraph.
- Keep the existing layout and the port 5000 setup from the sample app.

REFINEMENTS (what changed between versions and why)
---------------------------------------------------
Before v1: We tested anonymize_text() on its own first. Two things shaped
          the prompt. An empty entity list makes Presidio scan for every
          entity type, not just ours, so requirement 5 tells the app to fall
          back to our five entities. Whitespace only text also had to come
          back unchanged, so requirement 4 lists it.
v1 -> v2: The sample web app called anonymize_text() directly and had
          different default entities (PERSON, EMAIL_ADDRESS, PHONE_NUMBER).
          The follow up prompt makes it use our redactor so the web app
          follows the same rules as the command line and the tests.
Testing: We ran 21 unit tests and tried the web app with normal text, mixed
          entities, an unsupported entity (CREDIT_CARD), empty text, and
          text with no PII. All behaved as expected.
Known limitation: Presidio sometimes tags the word "NINO" itself as a
          LOCATION (for example "my NINO is AB123456C"). The NINO number
          is still redacted correctly, so we documented this and kept our
          tests on sentences that avoid the issue.
